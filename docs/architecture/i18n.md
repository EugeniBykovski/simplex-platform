# Internationalisation: English and Russian

Retained by owner decision: Russian routes are not indexed until translated content is reviewed and approved. The design is English only, so **all Russian copy and every Russian layout check are new work with no approved reference.** The routing foundation is built and verified. Page copy arrives with each page ticket.

## Decisions

| Decision | Choice | Why |
|---|---|---|
| Library | next-intl | Server component support, ICU plurals for Russian, typed keys, static rendering |
| URLs | `/about` (en), `/ru/about` (ru) | English keeps the approved design URLs unchanged |
| Slugs | English in both languages | Stable URLs, one route table. Translated slugs can come later if search data justifies them |
| Default locale | `en`, unprefixed. `/en/*` redirects | One canonical URL per page |
| Language detection | **Off**: no `Accept-Language` redirect, no locale cookie | Same URL always returns the same language, which keeps pages cacheable and crawlable |
| Switching | Explicit links in `LocaleSwitcher`, in the header at every width | Plain anchors, because `<html lang>` changes |
| Fonts | Geist and Geist Mono with `cyrillic` subsets | Verified: Google serves Cyrillic for both |

## How it fits together

| File | Responsibility |
|---|---|
| `src/i18n/routing.ts` | Locales, prefix mode, detection settings |
| `src/i18n/navigation.ts` | Locale-aware `Link`, `redirect`, `usePathname`, `useRouter`, `getPathname` |
| `src/i18n/request.ts` | Loads message namespaces per request |
| `src/i18n/translation-status.ts` | Per-family Russian status: `missing`, `draft`, `approved` |
| `src/i18n/messages/{en,ru}/*.json` | Interface strings by namespace |
| `src/proxy.ts` | Maps URLs to locales |
| `src/lib/seo/metadata.ts` | Canonical, hreflang and robots from translation status |
| `src/types/next-intl.d.ts` | Types `t()` keys against the English catalogue |
| `scripts/check-i18n.mjs` | Fails on drift between languages |

ESLint rejects `next/link`, `redirect` and `usePathname` from `next/navigation` under `src/`, because those silently lose the `/ru` prefix.

## Publishing gate

This keeps unreviewed Russian text from competing with English in search, and from making claims nobody has checked.

| Status | Page renders | Indexed | hreflang | Canonical |
|---|---|---|---|---|
| `missing` | No, returns 404 | No | No | n/a |
| `draft` | Yes, for review | No | No | Points to English |
| `approved` | Yes | Yes, if `SITE_INDEXABLE=true` | Yes, with `x-default` | Self |

Pages enforce `missing` by calling `isLocaleAvailable(family, locale)` before rendering, as `src/app/[locale]/page.tsx` does. `home`, `agent`, `services`, `packages`, `industries` and `work` are `draft` today. The page ticket that adds Russian copy moves its family to `draft`. A human review moves it to `approved`.

## Translation scope

Translate through the same claims register as English. A translated placeholder is still a placeholder, and `check-i18n` fails on `[bracketed]` text in Russian catalogues. Everything in `src/i18n/messages/ru/` today is a **machine-drafted first pass that needs a native editor's review.**

Never translate: `SimpleX`, `SimpleX Agent`, technology names (Next.js, Kafka), standard names (PCI DSS, ISO 27001, WCAG). Keep the logo in Latin script.

## Russian-specific rules

| Topic | Rule |
|---|---|
| Plurals | Always ICU with `one`, `few`, `many`, `other`. Verified output for 1, 2, 5, 11, 21, 22, 25 and 1.5: `1 проект`, `2 проекта`, `5 проектов`, `11 проектов`, `21 проект`, `22 проекта`, `25 проектов`, `1,5 проекта` |
| Numbers, dates, currency | `Intl` through next-intl's formatters, never string concatenation: `1 284`, `5 ноября 2026 г.`, `150 000 €` |
| Prototype strings to replace | `errPlural`, `' project' : ' projects'` and `' sample role'` are English-only logic in the design scripts. Use ICU instead |
| Sentence building | Never build sentences from fragments. `"Services we bring to {{d.name}}"` and `"What makes {{d.name}} hard."` break under Russian case endings. Give each slug its own full sentence |
| Typography | «Кавычки», em dash with spaces, non-breaking space after one-letter prepositions and between numbers and units |
| Uppercase | `.t-mono` and `.eyebrow` uppercase and letterspace their text. Check that Cyrillic stays legible |
| Tracking | Display tracking of `-0.052em` was tuned for Latin. Check it on Cyrillic and add a `:lang(ru)` override if the letters collide |
| Font features | `.sx` sets `ss01` and `cv11`. Check they do not affect Cyrillic forms |

## Layout risks

Russian is typically longer than English and has long single words. These are the places the design is most exposed. They become checks in [manual-qa.md](../qa/manual-qa.md). Any fix is an **adaptation, not approved design** (GAP-V04).

| Component | Risk | Mitigation |
|---|---|---|
| Header, 1101–1280 px | Eight links in a bar sized for short English labels ("Как мы работаем") can overflow before the 1100 burger | Measure at SF-142. Prefer tighter padding, then a higher burger breakpoint for `ru` only |
| `.t-display`, floor 54 px | A 15-letter word needs about 450 px, wider than a 390 px screen | `hyphens: auto` with `lang="ru"`, `overflow-wrap: break-word`, and write short hero lines |
| `.btn`, `white-space: nowrap` plus `overflow: hidden` | Long labels get clipped silently | Allow wrapping for `ru` under 600 px, or keep labels short. Add a visual check |
| `.line-mask` headlines | Masks assume short lines; extra wrapping changes rhythm | Author Russian hero lines by hand |
| `.tabs`, `.filter-btn`, `.toggle-chip` | Rows wrap or scroll sooner | Already scroll or wrap. Check touch targets |
| `.cmp` tables | Column labels get longer | Already scroll below 600 px. Check the first column |
| Footer grid | "Политика использования cookie" in the base row | Base row already wraps |
| `.sched-day` | Day abbreviations | Use `Intl` short weekdays |

## SEO

- `<html lang>` is set per locale. Verified: `en` on `/`, `ru` on `/ru`.
- hreflang appears only for approved Russian pages, with `en`, `ru` and `x-default`.
- Open Graph locale: `en_US`, `ru_RU`.
- The sitemap (SF-153) lists a Russian URL only when its family is `approved`.
- Russian search also means Yandex. Add Yandex Webmaster verification in SF-153 if Russia is a target market.

## Owner decisions needed

1. **Target market (GAP-I02).** Is `/ru` for Russian-speaking buyers anywhere, or for clients in Russia? If the latter, get legal advice before launch on Russian personal-data rules (Federal Law 152-FZ, including its data-localisation requirements), and on whether the form and email processors are permissible. This matters most for contact and job forms, and it is a question for counsel rather than something this document can settle.
2. **Who reviews Russian copy (GAP-I01)?** The gate needs a named approver.
3. **Scope for launch (GAP-I03).** Recommended order if phased: shell, Home, Services, Contact, then the rest. Legal pages must be counsel-reviewed in Russian before any Russian form goes live.

## Adding a language

Add the code to `locales`, add `src/i18n/messages/<code>/`, and generalise `translation-status.ts` from Russian-only to per-locale. Nothing else is locale-specific.
